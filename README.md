# نظام إدارة عيادة الأسنان 🦷

نظام كامل لإدارة العيادة: عيانين، مواعيد، طابور انتظار، فواتير، مخزون بيتخصم تلقائي، خطط علاج، مصاريف، وتقرير أرباح.

## المميزات

**العيانين والعلاج**
- بروفايل كامل لكل عيان (بيانات، خريطة أسنان تفاعلية، سجل فواتير، سجل مواعيد)
- كشف عيانين متشابهين بالاسم وقت التسجيل (تفادي تكرار نفس العيان بغلطة إملائية)
- خطط علاج متعددة الجلسات: تجمع كذا فاتورة (جلسة) تحت خطة واحدة، وتوريك الموقف الكلي (عدد الجلسات، الإجمالي، المحصّل)

**المواعيد والطابور**
- جدول مواعيد + عرض تقويم شهري، مع كشف تعارض المواعيد تلقائيًا
- طابور انتظار حي (Realtime): شاشة الدكتور والسكرتيرة بتتحدث لحظيًا لحظة ما حد يتضاف للطابور أو يبدأ كشف، من غير أي تحديث يدوي

**الفواتير والمخزون**
- فاتورة لكل عيان، وأي بند فيها مرتبط بخدمة (زي "حشو") بيخصم تلقائيًا من المخزون
- صفحة مخزون بالكميات، وتنبيه لما صنف يقرب يخلص (مع إمكانية تجاهل التنبيه ليوم واحد)
- إلغاء فاتورة بيرجّع المخزون المخصوم منها تلقائي مع سجل حركة واضح

**التقارير والمتابعة**
- تقرير أرباح (دكتور بس): الفواتير، المُحصّل فعليًا، تكلفة المخزون المستهلك، المصاريف، وصافي الربح
- رسم بياني لإيرادات آخر 7 أيام في الداشبورد
- جرس تنبيهات في أعلى الصفحة: مواعيد النهاردة، أصناف قربت تخلص، فواتير مش متحصلة
- سجل تدقيق (Audit Log) لكل عملية حساسة في السيستم (دكتور بس)

**الإدارة (لوحة الأدمن)**
- وضع صيانة يقفل السيستم مؤقتًا (مفيد وقت أي تحديث على الداتابيز)
- تصدير نسخة احتياطية كاملة بصيغة Excel لكل الجداول

**عام**
- 3 صلاحيات دخول: **دكتور**، **سكرتيرة**، و**أدمن** (تفاصيل تحت)
- وضع ليلي (Dark Mode)
- واجهة عربية بالكامل (RTL) بخط Cairo
- PWA (ممكن تتثبّت كتطبيق على الموبايل)

## الصلاحيات الثلاثة

| الدور | بيشوف إيه |
|---|---|
| **دكتور** | كل حاجة: عيانين، مواعيد، طابور، فواتير، مخزون، **+ الأرباح والتقارير + سجل التدقيق + إدارة الموظفين** |
| **سكرتيرة** | عيانين، مواعيد، طابور، فواتير، مخزون — من غير الأرباح أو سجل التدقيق |
| **أدمن** | بس وضع الصيانة والنسخة الاحتياطية — مالوش دخول على بيانات العيانين أو الفواتير خالص |

الدكتور والسكرتيرة بيتعملهم حساب من داخل السيستم (صفحة "الموظفين"). حساب **الأدمن** لازم يتعمل يدوي من SQL Editor (تفاصيل في خطوة 3 تحت) — ده مقصود، عشان محدش يقدر يدي نفسه صلاحية أدمن من جوه التطبيق.

## الخطوات بالترتيب

### 1) إنشاء مشروع Supabase
1. روح على [supabase.com](https://supabase.com) واعمل مشروع جديد.
2. من **Settings > API** خد:
   - `Project URL`
   - `anon public key`
   - `service_role key` (ده سري جدًا، متشاركوش مع حد ومتحطوش على GitHub)

### 2) تشغيل قاعدة البيانات
من Supabase Dashboard روح على **SQL Editor**، وشغّل كل ملفات `supabase/migrations/` **بالترتيب من الرقم الأصغر للأكبر**، كل ملف لوحده (تفتحه، تنسخ محتواه، تلصقه، تضغط Run، وبعدين اللي بعده):

```
0001_init.sql
0002_inventory_soft_delete.sql
0003_app_settings.sql
0004_dental_chart_and_audit.sql
0005_performance_indexes.sql
0006_appointment_duration.sql
0007_cancel_invoice.sql
0008_prevent_negative_stock.sql
0009_similar_patients.sql
0010_admin_role.sql
0011_admin_permissions.sql
0012_record_payment_and_restock.sql
0013_low_stock_dismiss.sql
0014_payments_and_booking_source.sql
0015_queue_entries.sql
0016_final_hardening.sql
0017_treatment_plans.sql
0018_queue_realtime.sql
0019_final_review_fixes.sql
```

⚠️ الترتيب مهم جدًا — بعض الملفات بتعدّل على دوال أو جداول اتعملت في ملفات قبلها.

### 3) عمل الحسابات الأساسية

**أ) حساب الدكتور الأول:**
1. من Supabase Dashboard روح **Authentication > Users > Add user**.
   - حط الإيميل وكلمة المرور اللي هتستخدمها للدخول، وفعّل "Auto Confirm User".
2. انسخ الـ `User UID` بتاعه.
3. روح **SQL Editor** وشغّل (غيّر القيم):

```sql
insert into profiles (id, full_name, role)
values ('USER_UID_من_هنا', 'اسم الدكتور', 'doctor');
```

**ب) حساب الأدمن (اختياري، بس لازم لو هتستخدم وضع الصيانة أو النسخة الاحتياطية):**
نفس الخطوات بالظبط (Add user → انسخ الـ UID)، بس وقت الإضافة في `profiles` حط الدور `admin`:

```sql
insert into profiles (id, full_name, role)
values ('USER_UID_من_هنا', 'اسم الأدمن', 'admin');
```

### 4) تشغيل المشروع لوكال
1. لازم يكون عندك [Node.js](https://nodejs.org) نسخة 18 أو أحدث متثبتة.
2. من داخل مجلد المشروع:

```bash
npm install
```

3. اعمل نسخة من `.env.local.example` باسم `.env.local`:

```bash
cp .env.local.example .env.local
```

4. افتح `.env.local` وحط فيه القيم اللي خدتها من Supabase في خطوة 1.

5. شغّل المشروع:

```bash
npm run dev
```

6. افتح المتصفح على `http://localhost:3000` وسجّل دخول بحساب الدكتور اللي عملته.

### 5) رفع المشروع على GitHub
```bash
git init
git add .
git commit -m "أول نسخة من نظام العيادة"
git branch -M main
git remote add origin https://github.com/USERNAME/REPO_NAME.git
git push -u origin main
```
⚠️ ملف `.env.local` متبعتش على GitHub خالص (موجود في `.gitignore` أصلاً) لأنه فيه مفاتيح سرية.

### 6) الرفع على Vercel
1. من [vercel.com](https://vercel.com) اعمل **New Project** واختار الريبو من GitHub.
2. في **Environment Variables** ضيف نفس المتغيرات التلاتة اللي في `.env.local`:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `SUPABASE_SERVICE_ROLE_KEY`
3. اضغط Deploy.

## إزاي تستخدم السيستم

1. **سجّل دخول** بحساب الدكتور → من صفحة "الموظفين" ضيف حساب السكرتيرة.
2. من صفحة **"الخدمات والأسعار"**: ضيف خدمات العيادة (حشو، خلع، كشف...) وأسعارها.
3. من صفحة **"المخزن"**: ضيف أصناف المخزون (حشو كومبوزيت، إبر بنج، إلخ) والكمية المتاحة.
4. لسه في نفس صفحة الخدمات: اربط كل خدمة بالصنف اللي بتستهلكه (مثلاً: خدمة "حشو" ← تستهلك 1 من "حشو كومبوزيت"). من غير الربط ده، المخزون مش هيتخصم تلقائي.
5. لما يجيلك عيان جديد: **"عيان جديد"** → املا بياناته (السيستم هيلفت نظرك لو فيه عيان اسمه شبه كده متسجل قبل كده).
6. **"الطابور"**: أضف العيان لطابور الانتظار (سواء جاي بموعد أو walk-in)، والدكتور من عنده يبدأ الكشف ويخلّصه — الشاشتين بيتحدثوا لحظيًا من غير refresh.
7. لما يخلص كشف/علاج: **"فاتورة جديدة"** → اختار العيان، وضيف بنود الفاتورة (اختار من الخدمات الجاهزة عشان السعر والخصم من المخزون يحصلوا أوتوماتيك، أو اكتب بند حر). لو العلاج محتاج أكتر من جلسة، اعمل **"خطة علاج"** من بروفايل العيان الأول وابعت كل فاتورة مرتبطة بيها.
8. صفحة **"الأرباح والتقارير"** (دكتور بس) بتوريك صافي الربح تلقائي.
9. لو محتاج توقف السيستم مؤقتًا (وقت أي تحديث)، أو تاخد نسخة احتياطية: سجّل دخول بحساب الأدمن وروح صفحة **"الإدارة"**.

## ملاحظات مهمة
- لو حبيت تضيف دكتور أو سكرتيرة تانيين في المستقبل، هتقدر من صفحة "الموظفين". حساب الأدمن بس هو اللي محتاج SQL يدوي (مقصود، لأسباب أمان).
- لو حصل خطأ 403 في أي صفحة، افحص إن حساب المستخدم عنده صف في جدول `profiles` بنفس الـ `id` بتاعه في `auth.users`.
- وضع الصيانة بيمنع عمليات الفواتير والمخزون فعليًا لغير الأدمن، مش بس بيخفي الشاشة — مناسب تفعّله وانت بتشغّل migration جديدة.
- جرس التنبيهات وشاشة الطابور مش بيظهروا لحساب الأدمن (دوره إداري بس، مالوش صلاحية على بيانات العيانين).
